# 1440P 分辨率支持

支持 1280×720 和 2560×1440 的 16:9 游戏画面。将模拟器分辨率设置为其中一种，再启动 Alas；不需要修改按钮坐标、OCR 区域或游戏任务配置。画面应完整显示游戏内容，不包含额外的黑边、窗口边框或裁剪。

本实现采用统一识别坐标系的完整兼容方案。1440P 截图经方向校正后，在设备截图入口缩放到 1280×720；所有现有识别算法继续使用这一坐标系。操作指令在对应设备后端映射回实际分辨率。识别过程不保留 1440P 的全部细节；这与将全部模板和算法改为原生 1440P 识别是两种方案。

## 覆盖范围

| 路径 | 处理方式 |
| --- | --- |
| ADB、ADB_nc、uiautomator2、aScreenCap、aScreenCap_nc、DroidCast、DroidCast_raw、scrcpy、nemu_ipc、ldopengl 截图 | 通过公共截图入口校正方向、记录实际分辨率并归一化 |
| 按钮匹配、二值化匹配、亮度匹配、全图模板与多目标匹配 | 接收统一尺度的画面，使用现有资源、偏移和相似度阈值 |
| OCR、颜色检测、区域裁剪、遮罩 | 接收同一识别画面，区域与像素阈值保持一致 |
| 海图透视、网格与坐标计算 | 接收统一尺度的画面，沿用既有相机、网格、中心点和安全区域 |
| ADB、uiautomator2、Hermit 输入 | 在实际注入事件时转换成设备像素坐标 |
| minitouch、MaaTouch | 由触控构建器将识别坐标转换为握手返回的坐标范围，包含持续按压与多点触控 |
| HTTP minitouch | 继续发送 atx-agent 所需的归一化坐标，避免再乘一次分辨率倍率 |
| scrcpy 输入 | 按当前视频帧尺寸转换坐标，使用同一尺寸构造触控数据包；支持旋转后的逆向映射 |
| MuMu nemu_ipc 输入 | 先转换为设备像素，再由原接口完成其特有的轴转换 |
| 后宅持续按压 | 同时覆盖构建器和直接调用 uiautomator2、nemu_ipc 的路径 |
| Android 控件树 | 原生坐标点击直接通过 ADB 注入；登录流程中用于图像裁剪、拖拽的边界先换算到识别坐标 |

DroidCast_raw 按实际屏幕尺寸解码 RGB565 数据，不再固定为 720P。scrcpy 在 1440P 设备上请求 2560 宽的视频，并使用足以容纳该尺寸的 H.264 level 5；720P 保持原编码级别。硬件是否提供相应编码能力仍由设备决定。

## 开发约定

- `device.image`、按钮、OCR 区域、地图网格、手势路径、随机扰动和距离判断都使用 1280×720 识别坐标。
- `device.native_screen_size` 是设备的横屏实际尺寸。第一次截图之前需要操作时，会查询设备尺寸；重连会使缓存失效。
- `device.image_native` 保留最近一次截图经方向校正后的原始分辨率画面，可用于导出与排查。游戏识别应读取 `device.image`。错误截图队列也使用识别坐标系。
- 不要将 `SCREEN_SIZE`、`ASSETS_RESOLUTION` 或所有资源坐标整体乘二，也不要在业务模块重复缩放点击坐标。转换应发生在设备输入边界。
- Android 控件树边界本来就是原生坐标。`HierarchyButton` 点击直接注入；需要与 `device.image` 一起计算的边界使用 `device.logical_area()` 换算。
- 在运行中变更分辨率后，应重新启动 Alas，使编码器与触控服务重新握手。公共截图入口会检测尺寸变化，重连时也会清理尺寸缓存。

## 验证

在仓库根目录、项目 Python 环境中运行：

```bash
python -m pytest tests/device/test_resolution.py -q
python -m pytest tests -q
```

新增测试覆盖两种分辨率下的截图入口、识别区域、模板/遮罩/颜色/OCR 调用、原始帧解码、七种控制后端的点击/长按/滑动/拖拽、旋转、多点触控、控件树及后宅持续按压。识别测试使用可确定预期结果的合成画面，传输测试检查实际发送的坐标或协议数据包；这些测试不连接模拟器。

实机验证应分别在 720P 和 1440P 上检查：主页按钮落点、OCR 数字、后宅长按喂食、可滚动页面、海图拖拽与定位，以及你实际使用的截图/控制后端。不同游戏版本、DPI 或模拟器若产生非等比例的 UI 布局变化，仍需要真实截图定位具体差异。没有实机验证时，自动测试通过不能证明所有游戏场景都已正常运行。

### 本地只读验证

可以使用已有 Alas 的 Python 环境，在本次修改后的源码目录运行：

```powershell
& '你的Alas目录\toolkit\python.exe' dev_tools/resolution_probe.py --serial 127.0.0.1:16448 --adb 'adb.exe的完整路径'
```

也可以运行 `dev_tools/resolution_probe.bat`，按提示选择已有 Alas 的安装目录。已有截图可以通过 `--image native.png` 离线检查；国际服、日服和台服使用 `--server en`、`--server jp` 或 `--server tw`。

脚本保存原始截图、归一化截图、识别位置标注和 JSON 报告，并在 `log/resolution_probe/时间戳/resolution-report.zip` 汇总结果。主页可见时会执行金币区域 OCR，读数仍需与截图核对。脚本不发送点击、滑动、安装应用、改变分辨率或启动游戏任务，因此报告中的坐标映射只代表计算结果，不能视为操作后端已通过实机验证。
